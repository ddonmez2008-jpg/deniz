# FORMAT — IA Inquiry Process Document: house format (section by section)

> Source: the user's sample IA (uploaded 2026-11-01), used **for organization only**. Its topic, sources and wording are deliberately NOT stored and must never be reused.
> Each section below shows **(1) the house layout** taken from the sample and **(2) what that section must achieve** under the current criteria (IA_01–IA_05; the IA_03 exemplar is the quality benchmark). When giving feedback, keep the student in this layout but hold every section to the criteria column.

## Page order

| # | House layout (from sample) | Must achieve / rules (criteria) |
|---|---|---|
| 0 | **Title** in quotation marks at the top (a descriptive project title). | A title is optional; the inquiry question is essential. ⚠ The sample has a **"Candidate Number:"** line. The webinars say the candidate's name or number must **not** appear inside the IPD or video, so remove it unless the school's current upload rules say otherwise. |
| 1 | **SECTION A: Inquiry Focus** + a "Word Count: ___" line under the heading. | Per-section word counts are good practice. **A + B ≤ 1,500 combined** (A ≈ 300 is advice). |
| 1a | **Inquiry question** (bold, alone on its line). | Names a specific digital system + effect or issue + defined people + setting. Answerable, open, not double-barrelled. Avoid stacking several outcomes ("engagement, motivation, participation… comprehension, critical thinking, interaction"), because that breaks focus. |
| 1b | **Real-life example**: full reference + link first, then a paragraph describing the case. | Must state what happened, where, when, which system, who was affected. Cite at the point of use, **and end with an explicit sentence on how the example leads to the question.** No generic praise ("students are very lucky…"); report verified facts. |
| 1c | **Course Connections:** three sub-headings, each formatted *code + name: explanation*. Sample order: **Concept → Content → Context**. | The order of the 3Cs is flexible. Each needs the **correct syllabus code** (verify: e.g. AI = 3.6, Media = 3.5; Health = 4.4, Human knowledge = 4.5) and an *explained* link between the example, the people and the question. One principal C each. Use impersonal academic voice or "I", not "we/our study". No general intro and no extra "central case" section. |
| 2 | **SECTION B: SOURCES** | No introduction to B; start straight with Source A. |
| 2a | **SOURCE A / SOURCE B / SOURCE C**, each with its own "Word count: ___" line. | **Exactly three.** About 400 words each is a guide, but the B total must fit the 1,500 combined limit. |
| 2b | Full reference + URL directly under the source heading. | One consistent style (APA 7 in the sample). The URL must point to the **same** work as the reference. Check that the author, journal and link match. |
| 2c | Four sub-headings per source (house layout): **Description of the content in the source** · **Credibility of the source** · **Justification for the source's use in the inquiry** · **Methodology and Limitations** | Map them onto the two assessed jobs: **ANALYSIS** = Description (keep it short; summary earns little) + Credibility + Methodology & Limitations → claims and perspective, author expertise, purpose and audience, method and whether it supports the claims, specific limits, bias or interests, missing voices, and *how these change confidence*. **SELECTION & USEFULNESS** = Justification → which part of the question it answers, what evidence it adds, how it supports, challenges or complements the other sources, and **what it cannot establish**. ⚠ Generic lines ("valuable for any IA question", "reinforcing reliability" because of affiliation alone) score low. Usefulness must be specific to *this* question. Do not list extra 3C codes here; the 3Cs belong in A. |
| 3 | **Bibliography** (alphabetical, full references with URLs). | Must list **all** sources used in the IPD **and** the video (not just the three B sources), including the real-world example source, media, images and clips. |
| 3a | **Video sources / tools** list (editing, research and writing tools). | Acknowledge tools properly as references, with tool, version or year, purpose and date, following the AI-acknowledgement model at the end of IA_03. AI-generated material used in the work must also be identified at the point of use. |
| 4 | *(Not in sample; add when used)* **Appendices**. | Survey instrument, n, dates and selection; interview role, date, method, questions and transcript; AI-use log; optional presentation script. |

## Sub-heading wording to enforce (house layout + criteria-aligned labels)
```
"Project title"
SECTION A: Inquiry Focus            Word count: ___
  Inquiry question
  Real-world example and connection
  Course connections
    Concept — 2.x Name: …
    Content — 3.x Name: …
    Context — 4.x Name: …
SECTION B: Sources                  Word count: ___
  Source 1 — [title or description] Word count: ___
    Full reference
    Analysis (description · credibility · methodology & limitations)
    Selection and usefulness (justification)
  Source 2 — … (same)
  Source 3 — … (same)
List of references (IPD + presentation, alphabetical)
Acknowledged tools
Appendices
```
The user's four-heading version may be kept as-is *inside* Analysis / Usefulness if the school requires it. Feedback should still judge the content against the two assessed jobs.

## Known failure patterns seen in the sample format (check every student for these)
1. A + B total over 1,500 (sample: 320 + 455 + 444 + 419 = 1,638). Everything past 1,500 is not credited.
2. Wrong syllabus codes.
3. Reference ≠ URL ≠ the author discussed in the text (source identity mismatch).
4. Description-heavy source sections; credibility argued from prestige or affiliation only.
5. Usefulness not tied to a specific part of the question.
6. An identifying field (candidate number) inside the IPD.
7. Spelling and terminology slips that hurt clarity (e.g. "IA tools" for "AI tools", "meat-synthesis", "traits" for "trials").
